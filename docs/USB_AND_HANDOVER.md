# 核心能力：有线与无线接续

这是正式发布硬门槛，未打通普通权限 USB 通道之前，不把局域网预览宣称成完整产品。

个人版已验证的 USB 通道使用 HDC 调试转发；它依赖开发者选项、设备授权和调试服务，不符合“商店下载安装后自然使用”的目标。上架版不内置或自动启动 HDC、不要求用户打开调试模式，也不修改系统 USB 设置。

[华为 USB 概述](https://developer.huawei.com/consumer/en/doc/harmonyos-guides-V14/usb-overview-V14)提供宿主访问所连接 USB 外设的能力。这不能证明普通平板应用可以在设备模式暴露自定义流接口，也不能证明 Mac 能以通用 USB 设备角色被平板访问。随后对官方API26 SDK的逐项检查发现：`@ohos.usbManager` 从API14公开了 `getAccessoryList / hasAccessoryRight / requestAccessoryRight / openAccessory / closeAccessory`，相关声明未标为systemapi。因而优先验证配件模式，而不是假设缺少公开接口。公开接口可编译仍不代表每台固件支持AOA或实际数据通路。

部分机型可[开启 USB 网络共享](https://consumer.huawei.com/cn/support/content/zh-cn11639869/)。可调查系统实际暴露并被 Mac 支持的 USB 网络接口，但这个设置并非所有型号、系统和 Mac 都相同；不能自动把 RNDIS、CDC-NCM 或 USB-C 接口名称当成可用性证据，不能要求关闭安全保护或安装未签名驱动。

当前代码层次：

- `shared/TransportPolicy.hpp`：只有正确配对身份、通过实际认证、支持普通用户使用且测量仍新鲜的线路参与选择。性能改善需超过20%，至少5秒切换间隔；拖动时推迟改善性切换，活动线路失效时可立即选可用备用线路。策略测试通过；已接入RNDIS候选探测与单路自动选择，实际切换体验仍须验证。
- `mac/Sources/StoreCapture.swift` 与 `main.swift`：异常断开时保留同一虚拟显示器至多10秒；正常结束立即释放，不保留采集或编码。新会话创建新密钥和计数。0.1.13实机拔线后保留原窗口并恢复无线画面；0.1.14接续时不再重复应用显示模式。
- 0.1.13当前设备的普通USB与已配对局域网均能传屏。只使用一条媒体线路，无线后台探测备用；拔线恢复已验证，自动插回及停顿改善仍待验收。

发布验收必须包括：仅无线启动→插线后台测量→切换到更优有线→拔线无线接续→插回再评估；窗口位置、显示器ID、按住拖动、键盘释放、鼠标形态、全屏与系统边缘手势、显式结束均须检查。还要覆盖不传数据的充电线、USB2/3、差Wi-Fi、多路由、系统休眠／旋转／后台、iPad随航并存。发现不支持的线或机型时自动保持无线并清楚提示，不能让用户手选底层协议。

## 新增USB配件研究代码

`harmony/.../store/HarmonyAccessory.ets` 使用公开配件接口，只在未来明确调用时请求对应配件访问授权；没有加入首页启动连接流程，不在后台申请权限。Mac的`mac/USB/AccessoryControl.cpp`只提供普通IOKit选定设备适配，不调用seize、不自动枚举或启动模式切换，尚未链接到GUI。

`usb/AccessoryProtocol.hpp`按[AOSP官方AOA说明](https://source.android.com/docs/core/interaction/accessories/aoa)实现有授权门控的协议探测和启动请求序列；`usb/StreamMux.hpp`提供控制／视频分流、分片解析、队列边界和公平调度。它仍需接入真实bulk端点、TLS流桥接、身份认证、测速和切换状态机。Android/AOSP文档只定义参考协议，不能证明HarmonyOS固件完全兼容。

特别注意AOA会让设备重新枚举，并可能与MTP传文件互斥。实现不得抢占正在工作的USB接口；首次使用需明确提示并取得系统访问授权。不能为追求“零操作”而偷偷打断用户文件传输。该早期AOA候选当时没有发送真实USB控制请求；后续RNDIS的实际控制请求与数据验证另见下文。


## 2026-10-18 普通权限 RNDIS 实验

设备系统查询列出了 acm/ecm/hdc/mtp/ncm/ptp/rndis/storage；用户开启 USB 共享后真实枚举为 RNDIS（控制类224/子类1/协议3 + 数据类10），Mac 未自动建立网卡。应用内 IOUSBHost 适配已用普通接口访问完成 RNDIS Initialize/Query/Set，初始化返回 success、设备接收计数增长。没有 seize、USB 配置强改、HDC 转发或系统驱动安装。

新增 `mac/USB/StoreUSB.mm` 与保留 BSD 许可证的 lwIP 2.2.1：在用户打开 USB 共享时读取 USB 网络帧，独立网络栈只把本条 USB 连接的49563转到已有 TLS 服务的回环入口；回环入口还核对桥接连接源端口，原有证书固定和令牌认证不变。USB发现只传公开证书，首次连接仍需 Mac 点允许。USB 连接模式由系统控制，不能宣称商店应用可以静默切换它。

**0.1.13实测进展**：修正空地址发现崩溃及回环监听端口参数后，当前Edge实际获得DHCP地址并建立两条USB TLS流，持续传送画面，HDC没有连接。用户拔线后自动恢复局域网、原窗口位置保留，但反馈接续停顿明显。仅证明当前设备和模式，不代表其他机型已兼容。

新增候选线路探测只接受已经记住的 Mac 证书及令牌；响应需回显随机挑战。每条线路通过连续认证才参与选择，测量过期会剔除；有显著改善、满足最小停留时间且没有按住输入时才优化切换。线路失败时允许立即回退。显式结束不自动重连，异常切换在10秒显示器保留期内接续。仍须实测有线传屏与插拔全流程。

## 0.1.14接续停顿优化候选

已有显示器仍在线且物理像素匹配时直接复用，不重新应用模式或改变排列，移除原600ms显示器等待。平板会话期间每100ms只读取轻量原生生命周期位，断线后尽快启动备用通道；完整统计仍保持1秒采样，不改帧率计数。正常结束、后台或退出时取消快检查。

本机`handover-health.json`记录停止旧流到收到新流首个渲染确认的耗时与是否复用显示器；不记录地址、设备名称或凭据。该计时起点是Mac检测到旧流结束，并非用户拔线的物理瞬间。0.1.14构建通过，实际切换改善待安装验证。USB重新插入后能否自动恢复系统共享模式仍是发布门槛，不能只看画面正常就宣称已回到有线。
