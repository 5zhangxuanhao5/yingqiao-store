# 本地连接恢复候选 0.4.0-test.8（build 47）

2026-10-21：实机旧安装版出现局域网监听失败。系统日志为 Address already in use；映桥固定 TCP 媒体与待命端口恰被其他程序的临时出站连接使用。清除该次冲突连接、重启原映桥后，用户确认恢复；Mac 实际重新通过 USB 发送 3120×2080 画面。此记录属于 test.6 安装版的故障恢复，不是本候选的真机验收。

## 本候选修复

- 以 NWListener 实际 ready 状态判断本地媒体与待命服务是否可用。失败后禁用开始按钮，并显示“连接未就绪”；发现平板或已有录屏权限不能掩盖服务失败。
- 媒体/待命监听 ready 后再发布对应 Bonjour 服务；服务失败则撤下。监听不可用时不发送可连接的发现应答。
- 监听失败后释放失败对象，每 5 秒重试，最多 6 次。就绪后清除重试计时器，空闲稳定时不增加持续轮询。达到上限可手动刷新。
- 监听回调检查当前对象身份，旧监听器的失败/取消回调不能清掉新的实例。
- 重新建立待命服务时保留已存在的 USB 监听器，避免恢复过程把自己正在监听的端口再次绑定。

为保持现有平板协议兼容，本候选继续使用既有固定端口，没有实现任意端口回退；其他程序长期占用时不会强制断开该程序。新增就绪状态回归检查、本地 Intel/Apple Silicon 通用构建通过；云端构建另见对应 Actions 记录。test.7 的多机型兼容候选变更一并保留，但仍待新增真机验收。

没有把本候选安装到用户的 Pro、Air 或 Edge，原应用二进制和权限保留。当前故障已用原版本恢复，候选不自动替换。
