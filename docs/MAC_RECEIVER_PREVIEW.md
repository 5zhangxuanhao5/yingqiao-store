# Mac 接屏独立测试 0.4.0-test.4

这份候选用于让一台 Mac 接收另一台 Mac 的独立扩展桌面，保留原映桥和 iPad 随航。它使用独立应用标识、连接服务、配置目录和虚拟屏身份，不替换现有映桥或映桥完整版。

## 当前验证范围

- arm64、x86_64 编译通过，最低 macOS 13。
- 本机合成画面经过 TLS、AES-GCM、硬件编码、接收端解密和系统视频播放层，14 秒样本收到并提交 720 帧，播放层处于 rendering。
- 接收端解密和视频样本构建使用串行工作线程；每次处理完成后才读取下一块数据，避免界面线程承担视频处理或工作任务无限积压。
- 已验证几何尺寸选择、Annex-B 分割、分片/合并加密记录、重放/标签/长度拒绝。
- 真实 Air 全屏比例、跨机连接、四屏并行和实际桌面延迟仍待验收。以上合成测试不代表真实多屏效果已通过。
- 当前是局域网测试通道；接上线缆不代表已经形成 Mac 间有线网络。此版本不创建 Thunderbolt 网络接口。

## 使用

1. 两台 Mac 解压并打开“映桥-Mac接屏测试”。这是临时签名的开发测试包，尚未 Developer ID 签名和公证。
2. 提供桌面的电脑选择“向另一台 Mac 扩展”。该测试应用需要独立授予录屏权限；接收端本身不需要录屏权限。
3. 接收电脑选择“接收电脑画面”，选择发现的发送端，点“连接并全屏”。
4. 发送端本人确认连接。接收端进入系统全屏后，以实际视口像素尺寸申请独立桌面，保持比例，不拉伸或裁切。
5. 发送端如需接收键鼠操作，授予该测试应用辅助功能权限。按 Esc 或“结束接屏”退出。

仅在会话中建立采集和编码；结束时释放该测试应用自己的资源。此候选不包含互联网远控、麦克风、系统音频或高权限助手。

## 已知边界

- 默认 60 FPS 目标和 40 Mbps 编码预算是策略值，不是对所有设备、网络和多屏负载的保证。
- 尚未实现 Mac 接收端的有线/无线接续；不得将平板端既有接续能力当作 Mac 接收端已完成。
- 平板返回桌面/息屏保留扩展桌面的需求单独处理中，本候选没有更改已安装平板应用。
- 首次发现的证书指纹由本地服务发布并在连接中固定校验；发送端每次都需要本人确认，不提供无人值守信任。

## 构建

恢复公开仓库源码及原有 native-dependencies 资源，运行：

```sh
YQ_MAC_RECEIVER_PREVIEW=1 bash mac/build.sh
```

输出在 `mac/build/映桥-Mac接屏测试.app`。不设置该变量时仍构建原映桥入口。签名材料、SSH 连接文件、设备配置及运行数据均不在源码或安装包内。

## test.2 变更和实际状态

- test.1 的真实 Air 测试出现黑屏，尚未通过设备验收。发送端当时没有持续的视频连接；不能将本机合成测试当作真实成功。
- test.2 缓存所选电脑的连接信息，在全屏完成后确认视口并检查启动流程，增加连接/错误的可见文字及不含令牌的本机阶段诊断。
- 可选测试启动参数只会匹配指定证书指纹的发送端，发送端仍须确认连接；不自动信任其他电脑。
- test.2 的真实设备结果仍待验证，未更改稳定映桥及映桥完整版。

## test.3 变更和状态

- 真机日志确认：接收端曾尝试旧服务端口，并报告 Local network prohibited。test.2 没有通过真实接屏验收。
- 连接前重新解析所选 Bonjour 服务，发送端测试入口使用独立固定端口；网络等待和首帧超时显示原因，不再无限黑屏。
- 接收视口改为可接受键盘焦点的无边框整屏窗口，申请实际整屏像素尺寸，避免原生全屏预留顶部安全区域后使用较小内容高度。摄像头物理缺口无法显示图像。
- 此版本仍需要两台 Mac 各自允许局域网访问；发送端需要录屏，键鼠控制需要辅助功能。只有本人可以完成系统认证。
- 尚未通过真实 Air、四屏独立性和多屏负载验收。

## test.4 启动检查

- 真实接屏、输入、多屏性能及 Edge 后台恢复均不能仅凭本版本的编译/源码检查宣称完成。
