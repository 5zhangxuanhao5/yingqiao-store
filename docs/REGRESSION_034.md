# 映桥 0.3.4（25）输入与连接修复候选

## 实测问题与原因

0.3.3 通过正式包体合法性检查后，已保留数据安装到公开版 Edge 应用。用户实测触控板按压拖动无效，并频繁显示建立连接。此次未通过验收，未提交应用审核。

- 原先按压拖动通过的测试包含专用 easyGo 输入配置；正式 SDK 不接受该字段，0.3.3 使用空 common 配置，发生鼠标转触摸兼容差异。正式版不能沿用隔离 SDK schema 扩展作为已通过的依据。
- 正式包关闭了 ORIGINAL_USB_TEST，但本地待命管理器仍创建调试 USB 连接。实机 Mac 同时报告调试 USB 与 LAN 就绪，平板画面计数约每16秒复位：切入正式策略不接受的调试回环地址失败，退回LAN，重试后循环。

## 本候选调整

- 调试 USB 的发现待命与实际传屏共同使用构建能力开关；普通正式配置不再把调试 USB 宣告为可选路径。普通 USB 网络研究模块保留，此项不是完成消费者 USB 的声明。
- 对系统转换成鼠标来源触摸的按压手势，使用官方光标限制接口临时允许指针在窗口内移动，通过触摸位移维持 Mac 指针连续，松开后恢复相对光标。普通触屏滚动/长按和触控板双指滚动的路径不变。这是兼容候选，仍需实机证明；边缘长距离拖动也需单独验证。
- 增加无按键内容、无坐标、无设备名和地址的临时系统日志计数，区分会话重建和兼容拖动。未恢复输入轨迹文件持久化。
- 安装说明明确 Mac 从 GitHub 下载，Apple开发者付费账号不是提供下载的前提；保留未公证披露和 Apple 官方单应用打开说明。

- 原厂未修改 SDK 构建成功，0.3.4（25），tablet，easy_go仅common空对象，未新增权限，未恢复互联网远控或音频。
- 正式/调试两种能力开关的路径策略回归检查通过；不等于真实消费者USB或拖动验收。
- 本次设备绑定开发HAP SHA-256：`7321bb05d09182f75f3c08da1ec29fffe7c8c0167b4eaff1f726953bee0aeda0`。不公开含设备Profile的HAP、签名材料或运行凭据。
- Mac仍为0.3.2；个人完整版二进制、配置、授权保持原状。本轮用户已确认触控板按压拖窗、双指滚动和约1分钟保持连接正常。系统日志记录80次兼容拖动位移；随后90秒观察中会话generation保持1，采集实例未改变，Mac仅报告LAN就绪，未再出现此前约16秒周期切换。该观察不代表多网络长期稳定或边缘长距离拖动已全部通过。退出回收沿用既有流程，本轮未再单独复测。
